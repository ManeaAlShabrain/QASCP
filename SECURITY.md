# Reporting a security issue

Report suspected security issues privately to the repository owner via GitHub's private vulnerability reporting if it is enabled. If it is unavailable, use a private contact method agreed with the owner before sharing sensitive details. For customer deployments, follow the agreed incident contact and reporting process.

Provide the affected revision, scope, observed impact, and sanitized evidence. Keep customer data, credentials, and confidential material out of public issues, logs, and test fixtures. The owner records initial triage, evidence access, mitigation, remediation checks, and disclosure coordination.

The current repository is in P1. Refer to the [governance handbook](docs/governance/ENGINEERING_GOVERNANCE.md) for release blockers and incident handling.
